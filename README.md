# UNEST

**HOLD THE TOKEN. HATCH THE CHICK.**

An ERC-20 token whose holders are issued fully on-chain generative pixel chicks, on Ethereum
mainnet, over a Uniswap v4 pool.

```
100,000,000 UNEST held   →   1 egg, issued automatically
reveal (2,000,000 burned) →   6 traits + a reward weight, written on-chain
swap fees (2%)           →   95% holders · 3% official · 2% buyback & burn
```

The art, the traits and the metadata are generated by `UnestRenderer.sol`. There is no IPFS pin, no
image file and no metadata server. This website only decodes what the contract already returns.

---

## Contracts

The Solidity ships in [`/contracts`](./contracts), so you can diff what is deployed against what is
published.

| File                           | What it is                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| `Unest.sol`                    | The ERC-20, and the controller: issues and burns eggs as balances move, splits fees, pays rewards |
| `UnestNFT.sol`                 | The ERC-721. Commit–reveal metadata seeded from a block hash                                      |
| `UnestRenderer.sol`            | The art. Six traits and a full pixel SVG, generated from the seed                                 |
| `UnestMarket.sol`              | Buy/sell router over the v4 pool; also runs buybacks                                              |
| `LaunchGuardHook.sol`          | The Uniswap v4 hook: validates the pool, tracks buy credit inside the swap                        |
| `PermanentLiquidityLocker.sol` | Seeds the LP and locks it permanently                                                             |

**The website does not deploy or contain these contracts.** It reads them.

## Going live is one file

There is no code change between "not deployed" and "live". Fill in `.env.local`.

```bash
cp .env.example .env.local   # then paste the real addresses
```

| Left empty                             | What happens                                                             |
| -------------------------------------- | ------------------------------------------------------------------------ |
| `NEXT_PUBLIC_UNEST_ADDRESS`            | balances, rewards and claiming are disabled                              |
| `NEXT_PUBLIC_NFT_ADDRESS`              | `/eggs` reads nothing and says `NOT CONFIGURED`                          |
| any other address                      | that registry row shows a placeholder, with no explorer link             |
| `NEXT_PUBLIC_RPC_URL`                  | viem's public endpoint is used, which will rate-limit under real traffic |
| `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID` | only injected wallets — the connector is not registered at all           |

Addresses are validated against `/^0x[a-f0-9]{40}$/i` **before** they are used, so a typo degrades
to `NOT CONFIGURED` rather than producing a bad transaction. **No address is invented anywhere in
this codebase**, and there is no demo data: if the chain cannot answer, the interface says so.

`NEXT_PUBLIC_NFT_ADDRESS` is deployed by the token's constructor — read `nft()` on the token to get
it.

## How the interface reads the chain

```
useEggs(owner)        balanceOf → tokenOfOwnerByIndex → per token:
                      tokenURI, revealSeed, revealBlock, nftRewardWeight, pendingReward
                      batched into multicall by wagmi. No indexer: enumeration is per-owner.

useProtocolStats()    token totalSupply + totalRewardWeight, nft totalSupply + nextTokenId
```

`tokenURI` returns `data:application/json;base64,…` carrying a base64 SVG.
[`src/lib/onchain/tokenUri.ts`](./src/lib/onchain/tokenUri.ts) decodes it, and returns `null` rather
than guessing when anything is malformed.

## Transactions

Every action runs `simulate → write → wait for receipt`. A call that would revert never reaches your
wallet — the button says `WOULD REVERT` instead.

Neither `reveal` nor `claim` pulls UNEST through an allowance (the token burns the reveal fee itself
from inside the call), so there is no approve step, and none is invented.

Nothing is faked: no simulated transaction, no fabricated hash, no confirmation that did not happen
on chain.

## Things worth knowing before you ship

- **Revealing needs headroom.** `payRevealFee` requires `balance ≥ eggsHeld × 100M + 2M`. Without
  the spare 2M, revealing would drop you under your backing and burn an egg. `/eggs` checks this and
  warns before you sign.
- **The reveal window is 256 blocks.** Block hashes are only readable that far back. Past it,
  calling `reveal` reschedules to a new target block instead — so it takes two transactions. The UI
  labels that button `RESCHEDULE`.
- **Eggs burn on the way down.** Selling or sending UNEST below your backing burns eggs
  automatically, newest first, and redirects their unclaimed rewards to the buyback.
- **The collection starts empty.** On launch day `totalSupply` is 0 and there is nothing to show
  until someone buys.

## Design

Tokens in `src/styles/globals.css` are taken from `UnestRenderer.sol`, so the site and the chicks
share one palette.

```
--bg     #0d0f11      --gold   #f2b705   (Gold shell)
--cream  #f5f0dc      --cosmic #8e46ff   (Cosmic shell)
--sky    #5dade2      --green  #58d68d
```

Press Start 2P for display, Inter for body, system mono for addresses and code.

> `next/font` downloads fonts at build time. A machine that cannot reach `fonts.googleapis.com` will
> fail the build — self-host with `next/font/local` if you need fully offline builds.

## What this project does not claim

Not audited. Not risk free. No returns promised. No APR displayed, because none can be honestly
promised — rewards depend entirely on swap activity and can be zero. Verify every contract yourself
before interacting. See `/docs#risk`.
